# PuppetGo 关卡编辑器

React + three.js 编写的关卡编辑器，配合 Unity 版 PuppetGo 解谜游戏使用。

- 每格 0.66 m，实体严格对齐网格
- 默认创建第 1 层，可继续增加层数（最多 16 层）
- 每层以 2D 俯视图编辑：地面方块、1×1 箱子、玩家、士兵
- 默认左侧 2D 编辑、右侧 3D 实时预览；拖动中间分隔条调整宽度，也可最大化任一视图，布局会自动记住。
- 导出 / 导入 JSON 关卡文件，编辑内容自动保存在浏览器本地

## 运行

```bash
npm install
npm run dev
```

打开 http://localhost:5173

## 分屏与组件工具

- 顶部可选择“2D 编辑”“2D / 3D 分屏”“3D 预览”；视图内的最大化按钮与“恢复分屏”也可切换布局。
- 拖动分隔条改变左右比例；双击恢复各半，聚焦后用方向键微调。3D 保留相机角度，并随视图宽度调整画布和取景。
- 两个视图共享同一关卡，2D 放置、擦除和轨道修改会实时更新 3D。3D 已去除各层线框及半透明分层平面。
- 左栏按地形与装饰、角色与目标、箱子与玻璃、机关与触发器、激光发射器分组。组件属性位于右栏。
- 边界的形状与文字独立显示，“界”字始终居中且完整。

## 操作

- 左侧选择工具（地面方块 / 1×1 箱子 / 玩家 / 士兵 / 橡皮擦）
- 网格上左键放置、右键擦除
- 选中玩家/士兵后，可在左侧设置初始朝向（↑ → ↓ ←）
- 2×1×2 箱子放置前可在左侧选横向/纵向，选中已放置的箱子也可翻转方向
- 激光发射器（2×1×1 / 2×1×2）占 2 格：先选长边方向（横向/纵向），发射方向只能沿长边——横向射东西（← →），纵向射南北（↑ ↓）；翻转长边时发射方向跟着一起转（E→S→W→N），2D 中炮口格会高亮并显示箭头
- 触发器是 0.5×0.5×0.2 m 的半透明红色薄板：不占格（overlay），可与其他实体同格放置；与门/弹簧用“编号”配对
- 门（2×1×3）：占 2 格、高 3 格，放在某层会自动占用该层及上面两层；向长边两端打开，两端各预留 1 格“开门位”（虚线“开”标记，永远不能放别的东西），实际占用 4 格；与触发器同编号配对，压住开门、松开立刻关门
- 滑动组件（1×1×3 / 2×1×3）：3 格高，选中组件后点击右栏“编辑路线 / 轨道”，点击移动方向的目标格即可延伸直线轨道，中间点自动逐格补齐。两格滑块自身第二格也可作为首个轨道点。2×1×3 只能沿长边，轨道会检查整个机体的三层体积、途经障碍和网格边缘；右键轨道点或点击 × 删除该点及后续轨道。与触发器同编号配对，压住滑到末端，松开退回起点。
- 边界 / 饰品格子 / 路灯：1×1×1 纯装饰，不能放其他组件、玩家也不能走上去，不挡激光、不需要支撑（边界是紧贴场景的 1/2 格地板）
- 弹簧（1×1×1）带编号
- “编辑路线”工具：点选士兵后，点击空格按顺序添加巡逻路径点，右键路径点删除；方向 = 行走顺序，走完最后一点循环回起点；每个路径点可单独设置停留秒数
- 顶部“+ 层”新增一层，层标签可切换；删除本层会把上层整体下移
- 编辑第 2 层及以上时，网格上的半透明色块表示下一层已占用的格子（可取消勾选“显示下层占用”）
- 顶栏切换 2D 编辑 / 3D 预览；3D 中左键旋转、滚轮缩放、右键平移
- “用地面铺满当前层”可快速把该层填成地面
- “导出 JSON”下载关卡文件；“复制 JSON”直接复制到剪贴板

## 模型

地面、箱子、目标方块不使用 FBX，直接用基础立方体渲染（地面白色、箱子黄色、目标绿色），加载开销小。玩家和士兵使用 `public/models/` 下的 FBX：

| 实体 | 文件 |
| --- | --- |
| 玩家 | `ChinesePuppetBoy.fbx` |
| 士兵 | `Rockman@Idle.fbx`（动作）+ `Rockman.fbx`（网格及内嵌贴图） |

士兵优先使用指定的 Rockman FBX，覆盖旧的 Unity 士兵导出预览。`Rockman@Idle.fbx` 来自 `D:/Downloads/Rockman@Idle.fbx`，只包含骨骼与动作；网格复用项目 `PuppetGoUnity/Assets/Sprites/models/Rockman/Rockman.fbx`。编辑器把动作应用到同名骨骼，显示待机姿态，保留初始朝向与脚底对齐；每个士兵实例拥有独立骨骼。两个文件均已复制到 `public/models/`，此目录沿用仓库忽略规则，换机器运行时需要一并复制。

模型会被自动等比缩放并归一化到 0.66 m 单元格内，以模型底部对齐所在层。加载失败时编辑器会输出警告并使用占位方块；若之后替换了 FBX 文件，需要刷新页面（缓存按实体类型保留）。`Box.fbx`、`Target.fbx`、`BrickDirt.fbx` 已不再使用，可删除以减小项目体积。

## JSON 格式

```json
{
  "name": "tutorial_01",
  "cellSize": 0.66,
  "grid": { "width": 8, "depth": 6 },
  "layerCount": 2,
  "entities": [
    { "id": "g-0-0", "type": "ground", "x": 0, "z": 0, "layer": 0 },
    { "id": "b1", "type": "box1x1", "x": 3, "z": 2, "layer": 0 },
    { "id": "b2", "type": "box1x1x2", "x": 2, "z": 5, "layer": 0 },
    { "id": "b3", "type": "box2x1x2", "x": 0, "z": 4, "layer": 0, "rotation": 0 },
    { "id": "l1", "type": "laser2x1x1", "x": 5, "z": 0, "layer": 0, "rotation": 0, "facing": "E" },
    { "id": "tr1", "type": "trigger", "x": 3, "z": 3, "layer": 0, "number": 1 },
    { "id": "d1", "type": "door", "x": 4, "z": 2, "layer": 0, "rotation": 0, "number": 1 },
    { "id": "s1", "type": "slider2x1x3", "x": 0, "z": 4, "layer": 0, "rotation": 0, "number": 2, "track": [ { "x": 1, "z": 4 }, { "x": 2, "z": 4 } ] },
    { "id": "sp1", "type": "spring", "x": 0, "z": 5, "layer": 0, "number": 2 },
    { "id": "p1", "type": "player", "x": 1, "z": 1, "layer": 0, "facing": "N" },
    { "id": "s1", "type": "soldier", "x": 6, "z": 4, "layer": 0, "facing": "S", "route": [{ "x": 4, "z": 4, "wait": 2 }, { "x": 4, "z": 2 }] },
    { "id": "t1", "type": "target", "x": 5, "z": 5, "layer": 0 }
  ]
}
```

坐标约定：`x` 为列（0 起，向右），`z` 为行（0 起，向下），`layer` 从 0 开始，0 为第 1 层（地面层）。实体底部高度 = `layer × 0.66` m。目标方块表示玩家的胜利点：玩家移动到该格即过关。

士兵的 `route` 是巡逻路径点坐标列表（`[]` 表示站岗），方向由列表顺序决定：士兵面向下一个路径点移动，走完最后一个点后循环回起点。每个路径点可带 `wait` 字段（秒，0~60），表示士兵在该点停留的时间后再前往下一个点。

玩家和士兵带 `facing` 字段（`N`/`E`/`S`/`W`）表示初始化时的朝向，默认 `S`。3D 渲染按朝向旋转模型（假定 FBX 模型默认面向 +Z，即“南”；若模型默认朝向相反，需要翻转 `FACING_ROTATION` 映射）。

1×1×2 箱子占 1×1 格、高 2 格；2×1×2 箱子占 2×1 格、高 2 格，带 `rotation` 字段（`0` = 长边沿 X 横向，`90` = 长边沿 Z 纵向）。激光发射器有两种尺寸（2×1×1、2×1×2），都占 2 格、可推动，带 `rotation`（长边方向）和 `facing`（发射方向，`N`/`E`/`S`/`W`）。发射方向必须平行于长边：`rotation` 为 0 时只能 `E`/`W`，为 90 时只能 `N`/`S`；激光从“炮口格”（占地格中沿发射方向最靠前的一格）射出，1×1×2 的激光每个高度层一条光束，与 Unity `LaserSystem` 的判定一致。导入旧关卡时若 `facing` 垂直于长边，编辑器会自动纠正到长边轴（横向 → `E`，纵向 → `S`）。地面、箱子、目标、激光都是基础立方体：地面白色、箱子黄色、目标绿色、激光品红；玩家和士兵仍用 FBX 模型。

触发器是 0.5×0.5×0.2 m 的半透明红色薄板（渲染在格子表面高度），**不占格**：可以和其他实体放在同一格，之后新增的同类机关（踏板、机关方块等）也沿用此规则。触发器与门/弹簧/滑动组件用 `number` 编号配对：选中触发器、门、弹簧或滑动组件后可在左侧设置编号（0~99，留空 = 未配对），编号相同的自动配对。门是 2×1×3（`rotation` 长边方向，向两端打开并预留开门位），滑动组件是 1×1×3 / 2×1×3，弹簧是 1×1×1 青色方块。开场时若箱子已压在触发器上，把箱子和触发器放在同一格即可，游戏侧会识别为开场已触发。

支撑规则：只有不可移动方块（地面方块、目标方块）允许下层镂空；可移动方块（1×1 箱子）下层不允许镂空。导出和复制 JSON 时，可移动方块会自动向下补地面支撑列（该格已有方块则不重复补），保证箱子不会悬空。2D 编辑中，下层镂空的可移动方块会显示红色警告标记。编辑器内仍只显示你实际放置的方块；导入包含补全项的 JSON 后，这些补全的格子会出现在场景中。
